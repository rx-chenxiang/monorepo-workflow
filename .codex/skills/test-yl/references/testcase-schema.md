# 测试用例 Excel 字段规范

## Sheet：测试用例

固定列：

| 列名 | 要求 |
|------|------|
| 序号 | 从 1 开始递增 |
| 标题 | 动词开头，说明被验证行为 |
| 目录 | 需求模块/平台/页面/功能模块组合，例如 `客户管理 / 后台 / 客户分配 / 批量分配` |
| 负责人 | 默认 `系统生成` |
| 前置条件 | 环境、账号、权限、数据、配置、开关 |
| 步骤描述 | 使用 `1. ...`、`2. ...` 按序号换行，优先使用 `在【xxx】页面，进行【xxx】操作` 格式 |
| 预期结果 | 使用与步骤相同的序号换行，尽量与步骤一一对应，明确页面表现、接口响应、数据变化、日志或状态 |
| 关联工作项 | 关联需求、测试点或工作项 ID，例如 `REQ-001,TP-001` |
| 优先级 | P0/P1/P2/P3 |
| 类型 | 固定枚举：回归测试/功能测试/性能测试/兼容性测试/易用性测试/安全性测试/稳定性测试/接口测试/自动化测试/安装部署测试/冒烟测试 |
| 标签 | 用例ID、平台、页面、功能模块、测试维度、风险、接口、数据表、灰度等关键词 |

Excel 的 `测试用例` Sheet 表头必须严格按以下顺序输出：

```text
序号、标题、目录、负责人、前置条件、步骤描述、预期结果、关联工作项、优先级、类型、标签
```

平台、页面、功能模块、测试维度、用例ID、测试数据、验证层级、备注等仍作为内部 JSON 字段和 Markdown/脑图内容保留；写入 Excel 时合并到 `目录`、`关联工作项`、`标签` 或正文描述中。

## Sheet：结构化明细

固定列：

| 列名 | 要求 |
|------|------|
| 用例ID | `TC-001`，必须连续编号 |
| 平台 | 后台、APP、小程序、H5、接口、定时任务等 |
| 页面 | 需求中被验证的页面或接口/任务入口 |
| 功能模块 | 页面下的入口、列表、表单、详情、状态流、导入导出等 |
| 测试维度 | 固定枚举：功能入口/UI展示/交互效果/更新机制/连点测试/断网测试/正常场景/异常场景/旧版本兼容/影响范围/测试经验 |
| 测试数据 | P0/P1 必填，其他优先填写 |
| 验证层级 | 页面、接口、数据库、日志、队列、缓存、文件、通知中的实际核验点 |
| 备注 | 假设、风险、执行提示 |
| source_doc | 来源文档路径 |
| source_heading | 来源章节标题 |
| source_excerpt | 来源短摘录，不得复制大段原文 |

## Sheet：测试点覆盖矩阵

固定列：

| 列名 | 要求 |
|------|------|
| 需求ID | `REQ-001` |
| 需求名称 | 需求标题或业务规则摘要 |
| 功能点 | 可验证的最小测试点 |
| 数据表/接口 | 涉及接口、表、队列、缓存、开关；无则填 `无` |
| 测试点ID | `TP-001` |
| 关联用例ID | `TC-001,TC-002`；未覆盖则填 `无` |
| 覆盖状态 | 已覆盖/部分覆盖/未覆盖/待确认 |
| 说明 | 缺口、假设或覆盖理由 |
| source_doc | 来源文档路径 |
| source_heading | 来源章节标题 |
| source_excerpt | 来源短摘录，不得复制大段原文 |

## Sheet：二次核对报告

固定列：

| 列名 | 要求 |
|------|------|
| 核对维度 | 覆盖度、主流程、异常、权限、接口、数据表、安全、性能、兼容、灰度、文档冲突、待确认 |
| 核对结果 | 通过/部分通过/未通过/待确认 |
| 说明 | 给出统计、缺口、风险或人工复核建议 |

## JSON 输入结构

`scripts/write_testcase_workbook.py` 接受以下 JSON：

```json
{
  "test_cases": [],
  "coverage_matrix": [],
  "review_report": []
}
```

字段名既可使用中文列名，也可使用以下英文别名：

- `case_id` -> `用例ID`
- `module` -> `目录`
- `platform` -> `平台`
- `page` -> `页面`
- `function_module` -> `功能模块`
- `test_dimension` -> `测试维度`
- `title` -> `标题`
- `precondition` -> `前置条件`
- `test_data` -> `测试数据`
- `steps` -> `步骤描述`
- `expected` -> `预期结果`
- `verification_layer` -> `验证层级`
- `work_item` -> `关联工作项`
- `linked_work_item` -> `关联工作项`
- `linked_work_items` -> `关联工作项`
- `requirement_id` -> `关联需求` 或 `需求ID`
- `test_point_id` -> `关联测试点` 或 `测试点ID`
- `priority` -> `优先级`
- `type` -> `类型`
- `tags` -> `标签`
- `status` -> `状态`
- `owner` -> `负责人`
- `remark` -> `备注`

以下来源字段使用英文名，不做中文转换：

- `source_doc`
- `source_heading`
- `source_excerpt`

## 扩展 JSON 字段

除三张表数据外，JSON 可包含以下字段，供 Markdown、脑图和业务画像使用：

```json
{
  "meta": {
    "requirement_name": "需求名称",
    "project": "bss",
    "generated_date": "2026-07-03"
  },
  "business_profile": {
    "terms": [],
    "roles": [],
    "rules": [],
    "interfaces": [],
    "tables": [],
    "risks": [],
    "assumptions": []
  }
}
```

`business_profile` 应只记录文档中明确出现或经人工确认的信息；推断内容必须放入 `assumptions`。

生成前可参考 `references/json-generation-template.md`。机器校验可参考 `references/testcase.schema.json`；运行脚本时以 `scripts/validate_testcase_json.py` 的结果为准。
