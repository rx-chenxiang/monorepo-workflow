# 覆盖与优先级规则

## 优先级

| 优先级 | 含义 | 必测范围 |
|--------|------|----------|
| P0 | 核心冒烟 | 登录态、入口可用、主链路正向、关键保存/提交 |
| P1 | 版本必测 | 主流程负向、权限、关键业务规则、数据一致性 |
| P2 | 扩展覆盖 | 边界值、组合条件、兼容、一般异常、接口容错 |
| P3 | 低频边缘 | 罕见异常、弱提示、低风险 UI、长尾兼容 |

## P0/P1 数量控制

- P0+P1 合计通常不超过总用例数的 30%。
- P0 只保留最核心的冒烟链路和版本阻断级用例。
- P1 只保留主流程负向、核心规则、核心权限、核心数据一致性。
- 边界值、组合条件、一般异常、普通兼容性优先放入 P2/P3。
- 若交易、权限、状态流转、批量删除等高风险需求导致 P0/P1 超过 30%，必须在“二次核对报告”说明原因和影响范围。

## 必须优先覆盖的风险点

出现以下内容时，至少提升到 P1：

- 金额、订单、支付、退款、结算、库存。
- 权限、角色、组织、数据范围。
- 状态机、审批流、任务流、重复提交。
- 批量导入、批量删除、批量修改。
- 灰度开关、配置开关、定时任务。
- 涉及用户隐私、手机号、身份证、账号密码、token。
- 后端接口有幂等、锁、事务、队列、缓存、回调。

## 常用测试维度

以下内容用于设计用例和填写“标签/备注”，不要直接写入“类型”列。“类型”列只能使用：回归测试、功能测试、性能测试、兼容性测试、易用性测试、安全性测试、稳定性测试、接口测试、自动化测试、安装部署测试、冒烟测试。

用例的“测试维度”列必须从以下枚举中选择，并在整体用例集中覆盖这些维度：

| 测试维度 | 生成要求 |
|----------|----------|
| 功能入口 | 菜单、入口按钮、路由、权限可见性、深链/跳转入口 |
| UI展示 | 字段、文案、状态、空态、加载态、错误态、布局展示 |
| 交互效果 | 点击、切换、弹窗、提示、禁用态、返回、刷新、输入联动 |
| 更新机制 | 保存后刷新、列表同步、缓存更新、轮询/推送、状态实时性 |
| 连点测试 | 连续点击、重复提交、防抖、幂等、按钮 loading 与禁用 |
| 断网测试 | 网络中断、弱网、请求超时、重试、离线提示、恢复后同步 |
| 正常场景 | 主链路正向、典型数据、核心成功路径 |
| 异常场景 | 参数错误、权限不足、状态不允许、脏数据、服务异常 |
| 旧版本兼容 | 历史数据、旧 APP、旧接口字段、老状态值、缓存数据 |
| 影响范围 | 关联模块、上下游流程、数据同步、报表/统计、通知 |
| 测试经验 | 历史易错点、类似功能缺陷、隐性边界、回归关注点 |

| 维度 | 生成要求 |
|------|----------|
| 功能 | 正向、负向、业务规则、状态变化 |
| 边界值 | 空值、最小值、最大值、边界值前后、超长、特殊字符 |
| 权限 | 无权限、只读、跨组织、越权访问、数据范围 |
| 接口 | 参数校验、响应结构、错误码、幂等、重复请求 |
| 数据 | 新增、更新、删除、回滚、关联表一致性 |
| 异常 | 网络失败、服务异常、并发冲突、脏数据 |
| 安全 | 注入、越权、敏感信息脱敏、上传限制 |
| 性能 | 大数据量、分页、批量操作、响应时间；没有性能要求时标记为待确认或按低优先级 |
| 兼容 | 浏览器、分辨率、移动/平板；纯接口需求可说明不适用 |
| UI | 文案、布局、禁用态、加载态、空态、错误提示 |

## 覆盖深度

- 多平台需求必须按平台拆分用例，例如后台和 APP 分别生成。
- 多页面需求必须按页面拆分用例，页面名称写入“页面”列，功能归属写入“功能模块”列。
- P0/P1 不接受只有页面点击和模糊预期的用例，必须写出测试数据和验证层级。
- 页面需求至少覆盖：默认态、成功态、失败态、空态、加载态、权限态。
- 表单需求至少覆盖：必填、格式、边界、重复提交、保存后回显、取消/返回。
- 列表需求至少覆盖：筛选、搜索、分页、排序、空数据、权限数据范围。
- 接口需求至少覆盖：成功响应、参数校验、错误码、鉴权、幂等、并发或重复请求。
- 数据表需求至少覆盖：新增/更新/删除结果、关联表一致性、事务回滚、历史数据兼容。
- 状态流需求至少覆盖：合法流转、非法流转、重复操作、并发操作、回退/撤销。
- 批量操作需求至少覆盖：全成功、部分失败、全失败、超量、重复数据、权限混合数据。
- 导入导出需求至少覆盖：模板、合法文件、格式错误、字段缺失、重复行、部分失败结果、导出权限。

## 二次核对要求

二次核对报告必须如实暴露问题。不要因为要交付 Excel 就把所有项写成通过。

推荐核对项：

- 需求总数、测试点总数、用例总数。
- 未覆盖需求。
- 未覆盖测试点。
- P0/P1 数量是否合理。
- 文档互相冲突处。
- 技术方案中出现但需求文档未说明的行为。
- 需求文档中出现但技术方案未覆盖的行为。
- 需要人工确认的数据准备、账号权限、灰度配置、第三方依赖。
