# 测试专家生成模式

## 需求拆解

先把文档拆成可验证对象，再写用例。不要直接把段落改写成用例。

拆解顺序固定为：平台 -> 页面 -> 功能模块 -> 测试点 -> 测试用例。

- 平台：后台、APP、小程序、H5、接口、定时任务等。
- 页面：需求中出现的每个页面都单独建一组用例；不要把多个页面混在同一条用例里。
- 功能模块：同一页面下按入口、列表、表单、详情、弹窗、状态流、导入导出、消息通知等拆分。
- 测试维度：从功能入口、UI展示、交互效果、更新机制、连点测试、断网测试、正常场景、异常场景、旧版本兼容、影响范围、测试经验中选择。

| 需求类型 | 拆解方法 |
|----------|----------|
| 页面入口 | 菜单可见性、路由访问、面包屑、默认加载、无权限访问 |
| 列表查询 | 默认数据、筛选项、组合筛选、重置、分页、排序、空态、数据范围 |
| 表单提交 | 必填、格式、边界、保存成功、保存失败、重复提交、回显、取消 |
| 详情/编辑 | 字段展示、编辑权限、只读态、保存后刷新、并发修改 |
| 导入 | 模板下载、合法文件、格式错误、字段缺失、重复行、部分成功、错误报告 |
| 导出 | 权限、筛选条件生效、字段完整性、大数据量、脱敏 |
| 接口 | 鉴权、参数校验、成功响应、错误码、幂等、并发、限流 |
| 数据表 | 主表、关联表、唯一约束、状态字段、软删除、事务回滚 |
| 状态流 | 初始态、合法流转、非法流转、重复操作、撤回/回退、终态保护 |
| 审批流 | 发起、通过、驳回、撤回、转交、超时、重复审批、权限边界 |
| 批量操作 | 全成功、全失败、部分失败、超量、重复项、混合权限、结果反馈 |
| 灰度/开关 | 开启、关闭、切换中、无配置、缓存延迟、开关权限 |
| 定时任务 | 触发条件、执行成功、执行失败、重复执行、补偿、日志 |

## 测试数据设计

每条 P0/P1 用例必须写明测试数据。不能只写“准备测试数据”。

| 数据类型 | 设计要求 |
|----------|----------|
| 正常数据 | 最小可通过数据、典型业务数据、完整字段数据 |
| 边界数据 | 空值、0、1、最大值、最大值+1、超长、特殊字符、中文/英文/符号混合 |
| 异常数据 | 不存在 ID、禁用状态、已删除数据、过期数据、脏数据、重复数据 |
| 权限数据 | 本组织、跨组织、本人、他人、只读、无权限、已离职/禁用账号 |
| 历史数据 | 老版本字段为空、历史状态值、迁移前数据、缺失关联数据 |
| 批量数据 | 全合法、全非法、部分非法、重复行、超数量、跨权限混合 |
| 并发数据 | 同一资源重复提交、多人同时编辑、状态已被其他人变更 |

测试数据字段建议写成：

```text
账号：销售主管 A，所属校区=北京一校区
数据：待分配客户 3 条，其中 2 条本校区、1 条跨校区
配置：客户分配开关=开启
```

## 权限矩阵

后台类需求默认做权限矩阵，除非文档明确无权限差异。

| 角色/范围 | 页面可见 | 操作可用 | 数据范围 | 接口访问 | 预期 |
|-----------|----------|----------|----------|----------|------|
| 超管 | 是 | 是 | 全部 | 成功 | 可完成全部操作 |
| 主管 | 是 | 按授权 | 本组织/下级组织 | 成功或按范围限制 | 只能处理授权范围 |
| 普通成员 | 视需求 | 视需求 | 本人/分配给自己 | 成功或拒绝 | 不得看到越权数据 |
| 只读角色 | 是 | 否 | 授权范围 | 写接口拒绝 | 按钮禁用或接口 403 |
| 无权限用户 | 否 | 否 | 无 | 拒绝 | 页面不可见或接口 401/403 |
| 跨组织用户 | 视需求 | 否 | 不含其他组织 | 拒绝 | 不得查询或操作跨组织数据 |

权限用例至少包含：

- 页面入口权限。
- 按钮/操作权限。
- 数据范围权限。
- 直接调用接口的越权校验。
- 跨组织或跨校区数据隔离。

## 接口与数据验证

涉及技术方案、接口、数据表时，用例不能只看页面结果。

| 验证层级 | 写法 |
|----------|------|
| 页面 | 列表、详情、提示文案、按钮状态、空态、错误态 |
| 接口 | URL/接口名、请求参数、响应 code/message/data、错误码 |
| 数据库 | 表名、关键字段、状态值、关联记录、事务回滚 |
| 缓存 | key、过期时间、更新/清理时机 |
| 队列 | 消息是否投递、消费结果、失败重试 |
| 日志 | 操作人、操作时间、对象 ID、失败原因 |
| 文件 | 导入错误文件、导出文件字段、文件名、编码 |
| 通知 | 短信、站内信、企微、邮件、模板变量 |

推荐预期结果写法：

```text
页面：提示“分配成功”，列表负责人更新为销售 B。
接口：assignCustomer 返回 code=0，data.success_count=3。
数据库：customer.owner_id 更新为销售 B，operation_log 记录操作人和客户 ID。
```

## 用例颗粒度

- 一个用例只验证一个主要行为。
- 主流程用例可以包含完整链路，但不要混入多个独立业务规则。
- 边界值可按字段聚合，但每个输入和预期必须写清。
- 权限负例可按角色聚合，但要写清每个角色的差异。
- 接口参数校验可按参数组聚合，避免每个字段机械拆成大量低价值用例。
- 高风险规则宁可拆细，低风险 UI 细节可以合并。

## 步骤与预期一一对应

步骤和预期结果都用序号换行，尽量保持相同数量和相同语义层级。

每个步骤优先使用固定句式：

```text
在【xxx】页面，进行【xxx】操作
```

推荐：

```text
步骤描述：
1. 在【客户分配】页面，进行【使用销售主管 A 打开页面】操作。
2. 在【客户分配】页面，进行【勾选 3 条本校区待分配客户】操作。
3. 在【客户分配】页面，进行【选择销售 B 并提交分配】操作。

预期结果：
1. 登录成功并进入客户分配页面。
2. 3 条客户被选中，提交按钮可用。
3. 页面提示分配成功，接口返回 code=0，数据库 owner_id 更新为销售 B。
```

避免：

```text
步骤描述：登录后提交
预期结果：成功
```

## 业务知识画像

每次生成用例后，提取可复用业务知识，更新业务画像，减少后续生成时的幻觉。

画像内容：

- 业务术语：模块名、核心对象、状态名、配置名。
- 角色权限：角色、组织范围、数据范围、操作权限。
- 核心规则：状态流转、校验规则、开关规则、边界约束。
- 技术对象：接口、数据表、队列、缓存、定时任务。
- 风险点：权限、金额、订单、批量、删除、并发、幂等、灰度。
- 待确认项：文档缺失、冲突、推断、需要人工确认的信息。

画像使用原则：

- 优先相信本次需求文档和技术方案。
- 画像只作为历史知识和术语补全，不得覆盖本次文档的明确描述。
- 画像中的推断必须保留“待确认”标记。
