# 质量保障测试执行

## 目标

使用本技能把“已有测试用例”推进为“已执行、有证据、有报告、可沉淀回归经验”的测试结果。后台、H5、App 等界面测试默认使用 Codex 的 `computer-use:computer-use` 电脑操控能力执行，不默认使用 Playwright。

如果还没有测试用例，先使用 `test-yl` 生成测试资产；如果已有需求、用例、环境信息或测试委托，使用本技能执行。

## 最小可执行输入

开始真实执行前，必须确认以下信息；缺失时先产出缺口清单或基于 `references/intake-template.md` 的测试委托单，不假装执行：

- 目标项目、需求名称、测试用例来源；优先使用 `test-yl` 生成的 JSON。
- 测试环境地址、登录入口、测试账号、账号角色与权限。
- 测试数据授权：是否允许新增、修改配置、调用接口造数、查库、改库、清缓存和清理数据。
- 设备/浏览器范围、是否需要弱网/断网/兼容性/埋点/截图录屏。
- 本轮执行等级和上线阻断规则。

## 执行等级

若用户没有明确范围，按语义推断执行等级；仍不明确时默认 `P0/P1 验收`。

- `冒烟验证`：只执行 P0、登录/入口、主链路、版本可用性和关键页面不崩溃。
- `P0/P1 验收`：执行 P0/P1、版本阻断项、核心负向规则、权限和数据一致性。
- `完整回归`：在 P0/P1 基础上按风险补充 P2/P3、兼容性、弱网、历史影响范围。
- `复测`：优先执行缺陷关联用例，再补跑受影响回归用例。
- `自动化回归沉淀`：只挑选客观、稳定、可重复造数或可固定环境的数据校验项。

## 工作流

1. **需求接收**
   - 读取用户提供的目标项目、需求名称、地址、账号、允许的数据操作、设备范围和验收风险。
   - 判断执行等级：冒烟验证、P0/P1 验收、完整回归、复测或自动化回归沉淀。
   - 如果存在阻塞真实执行的缺失信息，基于 `references/intake-template.md` 创建或更新测试委托单。
   - 不索要生产账号密码；优先使用测试环境和可丢弃测试数据。

2. **执行前检查**
   - 校验地址、登录入口、账号角色、后台配置权限、接口/文档访问权限，以及测试数据是否可修改。
   - 当用户提供地址或测试委托 JSON 时，运行 `scripts/preflight_env.py`。
   - 在触碰数据前先记录阻塞项。

3. **范围选择**
   - 先按已选择的执行等级确定范围，再优先处理 P0/P1 用例和版本阻断项。
   - 将剩余用例归类为必测、选择性执行、自动化回归候选、视觉/人工确认、暂不可执行。
   - 对 `test-yl` 导出的 JSON 使用 `scripts/summarize_testcases.py` 做范围摘要。
   - 消费 `test-yl` 输出时，遵循 `references/handoff-contract.md`。

4. **测试数据**
   - 业务可见数据优先通过后台界面配置。
   - 需要可重复造数时，优先使用接口准备测试数据。
   - 只有在明确授权且回滚方案清晰时，才直接修改数据库。
   - 测试数据使用可识别前缀，例如 `QA_YYYYMMDD_`。

5. **测试执行**
   - 优先执行 P0/P1；如果阻塞项导致继续测试价值很低，先暂停并汇报。
   - 留存截图、视频、页面 URL、页面文本、请求/响应片段和数据核验证据。
   - 浏览器界面、H5、App、后台页面测试默认使用 Codex 的 `computer-use:computer-use` 接管当前业务窗口或用户已打开的浏览器标签页；除非用户明确要求其他执行面，不主动使用 Playwright。
   - H5/App 页面点击默认只执行单次点击；若 Computer Use 返回点击确认超时，先读取 URL、页面文本、截图和日志判断是否已生效，不要对同一目标立即补点、双击或连续点击。
   - 使用 Computer Use 接管浏览器、H5/App 或后台页面时，点击动作必须是一次“按下-抬起”的单点操作；禁止使用双击、连续点击、长按、补点或会唤出 Chrome/DevTools/插件控制层的点击方式。若单点导致控制层出现，先由 Agent 自动收起控制层、恢复业务页面焦点，再继续按用例托管执行。
   - 接管用户已打开的浏览器测试时，优先复用当前业务标签页，不主动打开、切换或停留在 DevTools 控制层；除非用户要求排查控制台/网络面板，证据采集优先通过 Computer Use 的页面文本、截图和必要接口日志完成。
   - 用户明确授权处理腾讯滑块验证码时，读取 `references/tencent-captcha-slider.md`，按测试环境滑块流程执行并保存滑块前后截图、DOM 坐标和登录接口日志。
   - 使用 Computer Use 或用户明确要求的 Chrome 专用工具时，执行风险界面操作前遵循对应技能的连接、确认和用户接力策略。
   - 每个失败或不确定结果都按 `references/defect-template.md` 创建缺陷记录。

6. **回归沉淀**
   - 优先沉淀 Computer Use 可复用执行步骤、证据路径、稳定页面断言和需要人工确认的点。
   - 可稳定客观复核的断言包括：可见性、数量、排序、路由/URL、接口响应、空状态、不崩溃和数据持久化。
   - 主观视觉检查保留为人工确认项；只有用户明确要求自动化脚本时，才另行设计脚本方案。

7. **报告输出**
   - 使用 `references/test-report-template.md` 或 `scripts/build_test_report.py` 生成最终报告。
   - 生成最终报告前，先用 `scripts/validate_execution_result.py` 校验执行结果 JSON。
   - 报告包含通过/失败/阻塞/跳过数量、阻塞项、缺陷、证据路径、遗留风险和上线建议。
   - 发现可复用规则时，更新项目业务画像或测试知识库。

## 决策规则

- 如果缺少账号、地址或权限，输出精确的缺失项清单和可填写的测试委托单，不假装已经执行。
- 如果用户要求的执行等级超过当前环境或授权范围，先执行可覆盖部分，并将其余用例标记为 `阻塞` 或 `未执行`，同时说明原因。
- 如果测试会修改数据，执行前先说明数据准备和清理方案。
- 如果缺陷阻塞 P0/P1，立即汇报；只有低优先级测试仍有价值时才继续。
- 如果规则不在需求或技术文档中，标记为 `待确认`，并将测试结果与产品判断分开记录。
- 未经用户明确授权，不对共享数据执行破坏性清理。
- 未获得动作前确认或用户接力时，不通过界面自动化处理验证码、传输敏感数据、上传文件、删除/移动数据、修改账号/权限/支付/系统设置，或提交高风险第三方表单。
- 如果登录、验证码或浏览器权限弹窗需要人工帮助，在执行结果中将该步骤记录为 `human_assisted`。

## 资源说明

- `references/intake-template.md`：测试执行前需要用户提供的字段。
- `references/handoff-contract.md`：`test-yl` 与本技能之间的机器可读交接协议。
- `references/execution-workflow.md`：详细执行阶段和产出说明。
- `references/execution-result-schema.md`：执行结果 JSON 字段和校验规则。
- `references/browser-control-strategy.md`：CLI/API、Computer Use、Chrome 和人工确认的使用时机与方式；界面测试默认走 Computer Use。
- `references/tencent-captcha-slider.md`：用户授权后处理腾讯滑块验证码的测试流程、证据要求和结果判定。
- `references/defect-template.md`：缺陷记录格式。
- `references/test-report-template.md`：最终报告格式。
- `references/device-matrix.md`：推荐设备/浏览器覆盖层级。
- `references/risk-priority-rules.md`：严重级别、优先级和上线建议规则。
- `scripts/preflight_env.py`：检查地址和委托信息完整性。
- `scripts/summarize_testcases.py`：汇总 `test-yl` 测试用例 JSON，用于执行计划。
- `scripts/validate_execution_result.py`：校验执行结果、缺陷、阻塞项、证据和上线建议的一致性。
- `scripts/build_test_report.py`：从执行结果 JSON 生成 Markdown 报告。
- `scripts/collect_artifacts.py`：索引截图、视频、trace 和日志。
