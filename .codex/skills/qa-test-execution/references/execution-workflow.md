# 测试执行工作流

## 阶段 0：输入检查

- 收集测试委托单、需求文档、技术方案、测试用例和环境账号。
- 标记缺失项：地址、账号、权限、测试数据权限、接口/数据库访问、设备范围。
- 确认执行等级：冒烟验证、P0/P1 验收、完整回归、复测、自动化回归沉淀。
- 输出 `测试前置检查.md`，结论只能是：可执行、部分可执行、阻塞。

## 阶段 1：用例筛选

- 冒烟验证：执行 P0、登录/入口、主链路、关键页面不崩溃。
- P0/P1 验收：P0/P1 必测，先执行版本阻断项、核心负向规则、权限和数据一致性。
- 完整回归：在 P0/P1 基础上按风险和影响范围执行 P2/P3。
- 复测：优先执行缺陷关联用例，再补跑受影响回归用例。
- 自动化回归沉淀：筛选客观、稳定、可重复的数据断言用例。
- 主观视觉项：截图留证，交给确认人拍板。
- 缺少环境或数据的用例：标记阻塞并说明缺口。

## 阶段 2：测试数据准备

- 使用唯一前缀：`QA_{需求}_{YYYYMMDD}_{序号}`。
- 记录每条数据的创建方式、关键字段、关联账号和清理方式。
- 修改共享配置前记录原值，便于回滚。
- 不确定是否共享的数据，不直接删除。

## 阶段 3：执行与留证

- 每条用例记录：未执行、通过、失败、阻塞、跳过、待确认。
- 执行前先选择执行面：界面测试默认使用 Codex `computer-use:computer-use` 接管业务窗口或浏览器标签页；CLI/API 只用于稳定数据校验、接口核验、日志分析和测试数据准备；Chrome 专用 connector 仅在用户明确要求或 Computer Use 无法覆盖时使用。
- 使用 Chrome 或 Computer Use 时，遵守对应技能的连接、确认和用户接力规则；验证码、上传、敏感数据传输、删除/移动、权限/账号/支付/系统设置等风险动作必须动作前确认或交给用户。
- 失败必须记录：复现步骤、预期、实际、截图/视频/trace、接口响应、测试数据。
- 接口或数据规则必须补充接口响应、数据库/缓存/日志核验点，除非无权限。
- P0/P1 失败时立即汇报，不等整批测试结束。

## 阶段 4：缺陷与复测

- 缺陷按严重级别排序：S1 阻断、S2 严重、S3 一般、S4 轻微。
- 每个缺陷关联用例 ID、需求 ID、环境、账号、数据。
- 修复后优先复测失败用例，再跑相关回归用例。

## 阶段 5：回归沉淀

- 优先沉淀 Computer Use 执行步骤、证据路径、稳定页面断言、测试数据前缀和风险确认点。
- 稳定客观规则：元素存在、数量、排序、跳转、接口响应、空态、异常不崩溃。
- 主观判断保留人工确认：好看、自然、适当、符合感觉。
- 只有用户明确要求脚本化回归时，才另行设计自动化脚本方案。

## 阶段 6：报告

- 输出总览：通过率、失败数、阻塞数、待确认数。
- 输出缺陷清单：按严重级别和模块排序。
- 输出风险：环境限制、未覆盖范围、需求待确认项、上线建议。
- 输出附件索引：截图、视频、trace、日志、接口响应。
