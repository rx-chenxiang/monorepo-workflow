# 风险与优先级规则

## 严重级别

| 级别 | 含义 | 示例 |
|---|---|---|
| S1 阻断 | 主链路不可用或高风险数据错误 | 页面白屏、无法登录、核心提交失败、崩溃 |
| S2 严重 | 关键规则错误但有局部规避 | 排序错误、权限错误、错误数据展示、跳转错误 |
| S3 一般 | 非核心功能或局部体验问题 | 样式偏差、提示不准确、一般兼容问题 |
| S4 轻微 | 不影响使用的低风险问题 | 文案细节、轻微间距、低频边界 |

## 用例优先级

- P0：版本冒烟和主链路，失败通常阻断继续测试或上线。
- P1：关键业务规则、核心异常、数据一致性。
- P2：组合条件、兼容、弱网、边界、一般异常。
- P3：长尾场景、性能观察、历史经验补充。

## 上线建议

- **通过**：P0/P1 全通过，无 S1/S2 未关闭缺陷。
- **有条件通过**：仅存在已确认可接受的 S3/S4 或明确规避方案。
- **不建议上线**：存在 S1、核心 P0/P1 失败、严重数据/权限/支付/订单问题。
- **阻塞无法判断**：环境、账号、数据、接口权限不足导致核心测试无法执行。

## 自动化优先沉淀

- 高频回归主链路。
- 规则明确且结果客观的测试点。
- 曾经出过缺陷的场景。
- 容易被缓存、排序、权限、状态、时间边界影响的场景。

## 人工确认保留

- 视觉美观、布局舒适度、动效自然度。
- 设计稿未提供明确像素或阈值的 UI 判断。
- 需求中使用“适当、明显、合理、自然”等主观描述的点。
