# 可直接复制的提示词模板

将下方 `【】` 替换为实际内容后整段粘贴即可。落盘路径约定见 [docs/README.md](../../docs/README.md)。

---

## 模板一：生成【前端】技术设计文档

```
请按项目 Skill「writing-tech-design-doc」编写《【前端】技术设计文档》。

【上下文】
- 需求/迭代名称：【填写】
- 需求要点：【PRD 摘要或列表】
- 输出：默认写入 docs/bss/{需求名称}/技术设计方案/{需求名称}前端技术设计文档.md，并**必须**同步写入 docs/bss/{需求名称}/coding-plan/{需求名称}-coding.md（编码阶段提示词）；仅对话输出请说明

【要求】
1. 阅读 README.md 与 .cursor/rules、AGENTS.md、.cursorrules（存在的都读）。
2. 文档结构严格遵循 reference-template.md，与《【前端】技术设计文档示例》一致：§1 需求概述；§2 技术方案（含 2.1、2.2 功能开发方案实现及 2.2.1 下流程图/代码目录/**涉及到修改的接口（Apifox MCP）**/具体实现、2.3风险评估、2.4 影响范围）；§3 设计方案；§4 时间评估；§5 附件。
3. §3.1 第 1 条须保留「机型兼容写法：适配IOS13以上与安卓8以上，平板与手机机型」，并可展开说明。
4. 填写 §2.2.1「涉及到修改的接口」五列表前：若已启用 Apifox MCP，请通过 MCP 拉取接口信息；若无 MCP 则说明依据并列待确认。
5. 正文简体中文；复杂逻辑若需流程图/时序图等，须在正文中用 **mermaid 围栏代码块**嵌入（见 SKILL「流程图（Mermaid）输出规范」）。
6. 完成后将模板四写入 docs/bss/{需求名称}/coding-plan/{需求名称}-coding.md，并按 Skill 在回复中附加同内容「编码阶段提示词」代码块（可选）。

开始执行。
```

## 模板二：按技术设计文档编码

```
请根据本仓库技术设计文档实现前端功能。

【设计文档】
- 路径：【默认 docs/bss/{需求名称}/技术设计方案/{需求名称}前端技术设计文档.md】或【粘贴全文】

【本次范围】
- 只做：【】
- 暂不做：【】

【要求】
1. 阅读 README 与项目规则；遵守 §3.1 机型兼容（iOS13+、Android8+、平板与手机）。
2. 实现与 §2.2.1 接口表、§2.4 影响范围、§3 界面与体验一致。
3. 路由、api 目录与项目约定一致。
4. 完成后列出：改动文件、自测要点、未实现项。

开始实现。
```


## 模板四：编码阶段提示词（Agent 随文档自动生成）

**落盘**：填写后写入 `docs/bss/{需求名称}/coding-plan/{需求名称}-coding.md`（可与模板一、三配套；设计文档正文**不含**本段）。回复中可再用围栏代码块附一份便于复制。

**骨架（写入 `-coding.md` 时宜用围栏包一层，块内为可直接粘贴给实现 Agent 的正文，且据实填写 【】）：**

```
请根据本仓库《【前端】技术设计文档》实现功能。

【设计文档】
- 文件路径：【默认 docs/bss/{需求名称}/技术设计方案/{需求名称}前端技术设计文档.md；或「见本会话上文」】

【实现依据摘要】
- 需求：【名称】
- §3.1 机型兼容：【iOS13+、Android8+、平板/手机要点】
- §2.2.1 接口表：【要点；若来自 Apifox MCP 注明】
- §2.4 影响范围：【】
- §3.2 体验与操作：【摘要】

【本次范围】只做：【】暂不做：【】

【编码要求】
1. README + 项目规则；满足文档机型兼容与组件封装要求。
2. 与接口表及现有 api 封装一致。
3. 新页面登记路由；新接口按项目目录封装。
4. 完成后：改动列表、自测步骤、未实现项。

【待确认】【无则写「无，可直接实现」】
- 【】

开始实现。
```

## 给 Agent 的说明

用户索要「提示词」时从本文件给出对应模板原文。

撰写技术设计时：除正文外必须生成**已填写**的模板四，并**写入** `docs/bss/{需求名称}/coding-plan/{需求名称}-coding.md`；Apifox 与兼容要求见 SKILL.md。
