# 前端代码化自动化测试

## 目标

为前端项目建设可维护、可重复、可接入 CI 的代码化自动化测试能力。优先使用 Playwright E2E 覆盖用户真实路径，使用接口辅助造数和清理，使用组件测试覆盖复杂前端逻辑，并用报告、截图、trace、视频和测试数据治理保障长期回归。

## 默认判断

- 优先识别当前任务所属前端项目、技术栈、包管理器、启动命令、路由结构、登录方式和既有测试目录。
- 优先覆盖桌面 Chrome 场景，除非用户明确要求多浏览器、移动端或特定设备。
- 默认从 `登录`、`首页可达`、`菜单/路由`、`列表查询`、`新增编辑`、`表单校验`、`权限状态` 做 P0/P1 自动化。
- 默认输出可落地代码：Playwright 配置、Page Object、fixture、测试数据工具、spec、运行脚本和 CI 建议。
- 缺少测试地址、账号、权限或数据授权时，先输出自动化阻塞清单和需要的环境变量，不使用浏览器/电脑接管替代。

## 工作流

1. 明确任务类型：自动化方案、Playwright 骨架、E2E 用例、组件测试、接口造数清理、CI 接入、报告配置、flaky 治理。
2. 明确测试范围：项目、模块、需求、环境地址、账号角色、测试数据权限、运行层级、阻断标准。
3. 选择代码化测试层级：
   - 使用 Playwright 编写可重复运行的 E2E 回归。
   - 使用接口辅助准备测试数据、清理数据、验证持久化。
   - 使用 Vitest、Vue Test Utils、React Testing Library 等组件测试工具覆盖复杂组件逻辑。
   - 使用单元测试覆盖纯函数、映射规则、格式化、权限计算和状态转换。
4. 设计运行分层：`smoke` 只覆盖系统可用性，`regression` 覆盖核心业务链路，`full` 覆盖专项和边界。
5. 生成或修改代码时，沿用项目现有结构；没有现有结构时，使用 `references/playwright-patterns.md` 的目录和配置。
6. 自动化执行时，保存通过/失败/阻塞/跳过结果，失败必须关联截图、trace、视频或关键接口日志。
7. 将不适合自动化的主观视觉判断、验证码、外部人工审批、不可控共享数据场景标记为 `manual-only` 或 `blocked`，不要用 Codex/电脑接管绕过自动化边界。

## 不适用范围

- 不使用 Codex 浏览器工具执行冒烟、验收、复测或人工探索。
- 不使用电脑接管、Chrome 接管、手工点击来替代自动化脚本。
- 不输出以人工操作为主的测试报告；执行报告必须来自自动化命令、测试结果 JSON、截图、trace、视频或接口日志。
- 不把不可重复、依赖人工判断的步骤强行写成 E2E 阻断用例。

## 通用优先级

- P0：登录、首页可达、核心菜单可达、关键页面不崩溃、主流程入口可用。
- P1：列表查询、新增、编辑、保存、状态操作、表单校验、权限按钮、数据持久化。
- P2：导入导出、批量操作、复杂筛选、富文本、上传下载、跨页面联动、性能感知。
- P3：多浏览器兼容、弱网、视觉细节、历史边缘场景、低频配置项。

## 关键约束

- 不长期依赖 `.el-button:nth-child()`、DOM 层级、随机 class 或纯文案选择器；推动补充 `data-testid` 或稳定可访问性选择器。
- 不用固定 `waitForTimeout` 作为主要等待方式；优先等待 locator 状态、URL、接口响应或业务结果。
- 不在共享环境修改真实业务数据；自动化数据统一使用可识别前缀，例如 `QA_YYYYMMDD_`。
- 不把 flaky 用例直接作为发版阻断；先隔离、记录原因，再修复恢复。
- 不默认全并行执行涉及新增、编辑、删除的用例；先保证数据隔离后再扩大并行。
- 不依赖本地用户浏览器登录态作为长期方案；需要登录态时生成 `storageState`，或使用测试账号/API 登录固定化。

## 参考文件

- 需要落地 Playwright 目录、配置、POM、登录态、测试数据和 CI 时，读取 `references/playwright-patterns.md`。
- 需要设计自动化分层、判断哪些用例适合自动化、生成执行报告和治理阻塞项时，读取 `references/automation-workflow.md`。

## 输出要求

- 方案类输出应包含：目标、测试分层、用例分层、目录建议、数据策略、运行命令、CI 计划、风险。
- 代码类输出应包含：最小改动说明、关键文件、运行命令、环境变量、未执行验证说明。
- 执行类输出应包含：自动化命令、通过/失败/阻塞/跳过数量、证据路径、失败原因、修复建议。
